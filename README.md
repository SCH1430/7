# 1430 · Практикум

Рабочий тренажёр по информатике для 7 класса с банком из 3333 заданий: 28 исходных по предоставленным скриншотам, 40 прежних числовых версий и 3265 авторских учебных заданий по 32 моделям. Всего практика охватывает 42 семейства; в банке 1666 базовых и 1667 углублённых заданий. При каждом старте основные варианты случайно собираются из банка своего уровня: базовый — до 15 заданий и 45 минут, углублённый — до 13 заданий и 60 минут. Задания не повторяются между основными попытками ученика до исчерпания доступного банка уровня.

## Открыть тренажёр

Это статический сайт: `index.html`, `oge.html`, JavaScript, CSS и папка `assets/` находятся непосредственно в корне проекта. Для работы откройте опубликованный адрес GitHub Pages в отдельной вкладке современного браузера. Ученикам не нужны Node.js, npm или установка программы. Если сайт встроен в iframe, для полного экрана необходимо разрешение `allow="fullscreen"`.

Node.js нужен только для проверки и подготовки проекта сопровождающим: поддерживается версия 22+, GitHub Actions использует Node.js 24. Подробности публикации и команд проверки — ниже.

## Публикация на GitHub Pages

Корнем репозитория служит содержимое **папки `school1430-trainer`**: `index.html`, `oge.html`, `package.json`, `README.md`, папки `assets`, `.github`, `tools`, `tests` и `quality` находятся на одном уровне. Чистый комплект создаётся командой `npm run package:github` в `output/school1430-trainer-github.zip`. Внутри архива находится папка `school1430-trainer`; в репозиторий нужно перенести её содержимое, включая скрытую `.github`, без дополнительного вложенного каталога. Сам ZIP загружать в репозиторий не нужно.

Корневые HTML, JavaScript, CSS и `assets/` составляют сайт. В `tests/` сохранены проверки, в `tools/` — аудит, подготовка публикации, упаковка и генераторы материалов, в `quality/oge-audit.json` — проверка каждого из 400 заданий. Исходные скриншоты заданий находятся в `assets/sources/`, скриншот исходной инструкции — в `sources/original-instructions.png`. Временные результаты учеников, JSON-экспорты, PDF и снимки браузера из `output/` и `tests/` исключены из Git и чистого архива.

1. Создайте пустой репозиторий на GitHub с основной веткой `main` (поддерживается также `master`) и клонируйте его через GitHub Desktop.
2. Распакуйте ZIP, скопируйте всё содержимое его внутренней папки `school1430-trainer` в папку клонированного репозитория, затем создайте commit и выполните **Push origin** в GitHub Desktop. Проверьте, что `index.html` находится в корне репозитория. В материалах ОГЭ есть архивы 37 и 73 МБ: они больше лимита браузерной загрузки 25 MiB, но меньше лимита Git 100 MiB на файл. Git LFS для этих файлов не нужен. См. [ограничения файлов GitHub](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github).
3. В репозитории откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
4. Откройте **Actions → Check and deploy GitHub Pages → Run workflow**, выберите основную ветку. При последующих отправках в основную ветку публикация запускается автоматически. Если первая отправка была до включения Pages и завершилась ошибкой, повторите workflow после шага 3.
5. После успешного выполнения ссылка появится в **Settings → Pages** и в окружении `github-pages`. Для обычного репозитория адрес имеет вид `https://ВАШ-ЛОГИН.github.io/ИМЯ-РЕПОЗИТОРИЯ/`.

Workflow `.github/workflows/pages.yml` запускает `npm test`, проверку материалов, полный аудит 400 заданий, браузерные сценарии по адресу с подпапкой и конструктор. Для браузерных проверок runner автоматически устанавливает Playwright 1.62.1 и Chromium с системными библиотеками. Ошибка проверки останавливает публикацию; JSON-отчёты сохраняются в артефакте `validation-reports` на 14 дней. Перед загрузкой `tools/prepare-pages.mjs` собирает **только статические файлы в `output/pages-site/`**. Именно этот каталог публикуется; `.github`, `tests`, `tools`, `quality`, документация и временные результаты на сайт не попадают. Pull request запускает проверки без публикации. Развёртывание разрешено только из основной ветки; для другого имени ветки измените списки `branches`. Сайт обслуживает GitHub Pages; собственный домен и токены не нужны. Настройка основана на [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages) и [Playwright CI](https://playwright.dev/docs/ci).

Корневые файлы одновременно являются исходниками интерфейса и готовым статическим сайтом. Команда `npm run build` проверяет локальные ссылки с учётом регистра, изображения всех заданий, скачиваемые материалы, контрольные суммы ZIP/ODS/PDF и размер публикации, затем подготавливает `output/pages-site/`. Компиляция интерфейса не требуется. Все рабочие адреса относительные; проверен адрес с подпапкой `/school1430-trainer/`. Размер сайта — около **123,0 MiB**.

Ответы, история ученика и учительские правки сохраняются в браузере. При переходе с локального адреса на GitHub Pages перенесите нужные результаты через экспорт/импорт JSON. Учительский раздел не имеет серверной авторизации, а ключи находятся в клиентском коде; это учебный тренажёр.

Для локальной проверки используйте `npm test`, затем `npm run build`. Для полного аудита — `npm run audit:oge`. Браузерные тесты используют обычный установленный `playwright` или путь `PLAYWRIGHT_MODULE`, без привязки к имени пользователя. На Windows по умолчанию запускается Edge, на Linux/macOS — Chromium; `PLAYWRIGHT_BROWSER=chromium`, `msedge` или `chrome` меняет выбор. Если Playwright отсутствует: `npm install --no-save --package-lock=false --ignore-scripts playwright@1.62.1`, затем `npx playwright install chromium`. На Windows для Chromium задайте `$env:PLAYWRIGHT_BROWSER='chromium'`.

`npm run test:pages` автоматически создаёт временное HTTP-окружение только на время проверки и проходит основные варианты и ОГЭ по адресу с подпапкой: восстановление, JSON, PDF, файлы и Worker. `npm run test:focus` проверяет обзор с клавиатуры, ответы и черновики, полный экран, калькулятор, изображения, длинные условия, код, таблицы и поля файлов на ширине 320–1440 px. Снимки сохраняются в `output/focus-*.png`.

## Полный аудит 400 заданий ОГЭ — версия 2.9.2

`npm run audit:oge` заново проверяет каждое условие и выполняет настоящие браузерные проверяющие. Он создаёт `quality/oge-audit.json` с отдельной записью для каждого ID, результатами расчётов и контрольными суммами текущего кода и материалов. Успех требует покрытия **400/400**, всех **100 практических задач** и **125 сочетаний задачи/формата**: №13 проверяется и как презентация, и как документ. Для каждого практического случая проверяются правильный и содержательно неверный файл; ещё 25 программ Python решаются независимым алгоритмом. Техническая недоступность проверки не засчитывается как правильное отклонение неверного файла.

В №1–10 независимые парсеры пересчитывают данные непосредственно из условий: кодирование, все расшифровки, логические выражения, маршруты, все допустимые команды исполнителя, параметры запусков, адреса, поисковые множества и системы счисления. Исходная схема №9 визуально прочитана; независимая транскрипция стрелок привязана к SHA-256 изображения. В №11–12 ответы проверяются по реальным архивам, в №14 — по исходным строкам и вычислениям. Разборы и требования №13–16 сверены с настройками проверки.

Аудит выявил и исправил пропуски ODF-проверки: разные шрифты при требовании единого, интервалы заголовков и эквивалентную запись межстрочного интервала в пунктах, переходы SMIL, титул за границами слайда, устаревший кэш формул в исходных данных и в данных диаграммы. Отдельные регрессии проверяют как ошибочные файлы, так и допустимые формулы и перестановки категорий диаграммы. Версия ODF-проверяющего — 1.1.0; при открытии результата сохранённая проверка старой версии автоматически пересчитывается из вложений. Учительский балл сохраняет приоритет. При отсутствии исходного вложения показывается невозможность проверки, а прежний автоматический максимум не принимается на доверии.

Проверка оформления остаётся учебной: она оценивает доступные свойства ODF, а не смысл фотографии или текста. Тесты программ конечны. Эти ограничения указаны в критериях и диагностике; результат не выдаётся за полноценную экспертную аттестацию. Происхождение предоставленной копии ФИПИ и отсутствие побайтового сравнения с недоступным официальным архивом сохранены в `sources.json`.

Перед `npm run package:github` выполните аудит. Упаковка откажется использовать устаревший отчёт, повторно проверит ссылки и контрольные суммы файлов и создаст чистый ZIP плюс `output/github-package-manifest.json`. В архив входят исходники, тесты, материалы, workflow и итог аудита; история учеников, временные экспорты, снимки, кэши и `node_modules` в него не включаются.

## Возможности

- Светлая айдентика «1430 / практикум»: почти белый фон, графитовый текст и кобальтовый акцент. В обычной тренировке и ОГЭ задание занимает широкий рабочий лист с крупным заголовком, условием и ответами. Постоянные боковые панели убраны: сетка заданий открывается из шапки, черновик и калькулятор — возле ответа, в потоке страницы. Сохранены школьная принадлежность, адаптивность, видимый клавиатурный фокус и общий стиль главной, конструктора, результатов, учительского раздела и PDF.
- Банк из 3333 заданий: одиночный и множественный выбор, соответствия, числовые и текстовые ответы. У всех заданий есть навыки, сложность и ориентировочное время решения. Сложность и время назначены методически, статистической калибровки пока нет.
- Отдельный конструктор: любые 1–3333 задания из обоих уровней, фильтры по уровню, теме, навыку, сложности и происхождению, поиск по названию, теме, навыку, данным или ID, страницы по 24 карточки, просмотр условий, собственный порядок, название и время 5–120 минут. Можно сохранить подборку, скачать файл варианта и загрузить его на другом компьютере. Основные варианты собираются случайно; ручной конструктор использует именно выбранные задания. Выбор сохраняется при переходах между страницами; массовый выбор и снятие относятся только к текущей странице.
- Автоматическая сборка 1–30 заданий: темы распределяются поровну с разницей не больше одного. Есть ограничения по уровню, сложности, уникальности семейств и отметкам учителя. При смешанной сложности подбор стремится к 35% начальных, 45% стандартных и 20% сложных задач в пределах доступного банка; фактический состав показан в конструкторе. Невыполнимые требования возвращают понятную ошибку, текущая подборка сохраняется.
- Ввод только при активном окне, видимой вкладке и включённом Fullscreen API. Выход или потеря фокуса закрывают задания блокирующим экраном. Продолжение требует явного нажатия кнопки и возврата в полный экран.
- Автосохранение каждого изменения, восстановление попытки после перезагрузки. Таймер привязан к абсолютному времени и продолжает идти при блокировке и закрытии. Истёкшая попытка завершается автоматически при следующем открытии страницы.
- `beforeunload` запрашивает стандартное предупреждение браузера. Полностью запретить закрытие вкладки или достоверно отличить закрытие от перезагрузки сайт не может. Журнал описывает только наблюдаемые события.
- Калькулятор с безопасным арифметическим парсером (без `eval`), скобками, десятичной запятой и процентами.
- Условие разделено на текст, исходные данные, вопрос и формат ответа. Иллюстрации увеличиваются с клавиатуры или мышью в том же полном экране.
- Черновик отдельно для каждого задания: сохраняется после каждого изменения, восстанавливается с попыткой и блокируется вместе с ответами. Черновик не оценивается, но включается в PDF и файл результата.
- Перед завершением открывается обзор: заполненные, частичные, пропущенные и отмеченные задания. Из обзора можно перейти к нужному ответу; правильность до завершения не раскрывается.
- После завершения: оценка, правильные ответы и разбор каждого задания, фильтр ошибок. Для распространённых числовых ошибок есть конкретная диагностика; для множественного выбора показаны пропущенные и лишние элементы. Прочие ошибки объясняются сравнением ответа с условием и ключом без утверждений о неизвестном ходе мысли ученика.
- «Повторить ошибки» создаёт отдельную подборку из неверных и пропущенных заданий. Условия, ключи и редакции сохраняются из исходной попытки.
- PDF скачивается напрямую, содержит кириллицу, иллюстрации, ответы, оценку, диагностику ошибок, разборы, черновик и журнал. Библиотеки и шрифт находятся локально в `assets/`, внешняя сеть не требуется.
- Передача учителю: скачать PDF или экспортировать JSON; на другом устройстве открыть раздел «Учителю» и импортировать JSON. Баллы пересчитываются по ключам тренажёра.

## Основные варианты без повторов

Ученика определяют по ФИО и классу. Регистр, повторные пробелы, ё/е и пробел внутри названия класса нормализуются. Базовый и углублённый уровни учитываются раздельно. История восстанавливается из сохранённых завершённых попыток; дубли одного результата при импорте не расходуют банк повторно. Учитываются все выданные в завершённой попытке задания, включая пропущенные и решённые с ошибкой. Это охват банка, а не показатель освоения.

При старте базовый вариант берёт до 15 новых ID, углублённый — до 13. Пока все шесть тем доступны, они распределяются по 2–3 задания. Когда тема исчерпана, её места распределяются между оставшимися темами. Разные семейства предпочитаются; если в остатке есть только версии одного семейства, они могут встретиться в одном варианте. Один и тот же ID не повторяется до конца круга.

Последняя попытка круга короче, если новых заданий осталось меньше обычного размера: для полного текущего банка это 1 базовое задание после 111 полных вариантов и 3 углублённых после 128 полных. Только после завершения всего доступного банка следующий старт открывает новый круг. Задания со статусом «Нужна правка» не входят в доступный банк. Круг и прогресс показаны перед стартом и в результате.

ID и порядок фиксируются при успешном старте (`selectionMode: rotation-v1`, `bankCycle`) и сохраняются в попытке. Перезагрузка, блокировка, JSON, PDF и оценка используют этот состав. Активная незавершённая попытка продолжается, а не создаёт новую подборку. Старые фиксированные результаты и результаты `random-v1` остаются читаемыми и учитываются в истории.

Ручной/автоматический конструктор и «Повторить ошибки» позволяют намеренно вернуться к выбранным заданиям. Завершённые подборки тоже учитываются при следующем подборе основных вариантов по уровню каждого задания.

Прогресс хранится только в текущем браузере, авторизации и межустройственной синхронизации нет. Для другого устройства нужно импортировать файлы результатов ученика. Очистка данных браузера удаляет и историю банка. Импортированный JSON не является защищённым журналом.

## Задания с кодом

Python отображается отдельной панелью с моноширинным шрифтом, подсветкой, номерами строк и сохранением исходных отступов. Размер регулируется от 14 до 22 px и запоминается в браузере. Есть включаемый перенос строк, по умолчанию длинная строка прокручивается внутри панели. Панель используется в заданиях, банке, разборах и учительской форме. Номера строк декоративные; исходное условие и ключ не меняются, код не исполняется.

## Как устроен банк 3333

Сохранены все прежние ID и ключи; старые результаты открываются с прежним фиксированным составом. Новые ID имеют вид `pack-<модель>-<номер>`. Параметры фиксированы: условие не генерируется заново при запуске. Банк расширен с 1000 до 3333 заданий: добавлены 2333 версии с другими исходными данными. При расширении прежние 1000 записей были сохранены без изменения; при проверке 18.10.2026 уточнена только формулировка и разбор `advanced-4` без смены ключа. Количество версий зависит от модели и числа допустимых комбинаций. Это учебные версии по 32 моделям, а не 3333 разных методических типа.

Новые модели: перевод единиц, остаток оперативной памяти, целое число файлов, длина сообщений, минимальная длина кода, обратные задачи по тексту и звуку, перекодирование, передача данных, объём растра, палитра, назначение устройств, масштабирование, файловые пути и маски, URL, объём папки, логические условия и интервалы, перебор пар, линейные алгоритмы, циклы, целочисленное деление, декодирование, замена текста и таблицы.

У новых моделей нет отдельного исходного скриншота: в карточке учителя показано происхождение модели. Условия, данные и ключи проверены программно; отметка «Проверено учителем» остаётся отдельной ручной проверкой. Банк работает локально, без генерации в сети.

## Учительская проверка банка

В разделе «Учителю → Проверить банк» доступны исходные скриншоты, ключи, разборы, замечания и статусы «Ожидает проверки», «Нужна правка», «Проверено учителем». Из коробки ни одно задание не помечено проверенным учителем. Для подтверждения нужно указать имя проверяющего и отметить четыре пункта: условие, ключ, разбор, источник.

Можно заменить условие обычным текстом, исправить ключи и шаги решения. Формат и количество полей ответа остаются прежними; при замене текста иллюстрации сохраняются. Введённый текст экранируется и не выполняется как HTML. Правки хранятся редакциями, применяются после подтверждения учителем и фиксируются в новых попытках и экспортируемых вариантах. Завершённые попытки используют свои ключи: последующее редактирование оценки не меняет.

Для базовых № 13–14 полных оригиналов нет в предоставленных материалах. Нельзя честно восстановить неизвестный фрагмент. Адаптации сохранены и обозначены; для подтверждения карточки нужны полное условие от учителя и название/ссылка на полный источник. Сам исходный PNG остаётся неполным.

Карточки проверок можно скачать и загрузить на другом компьютере. Отметки и имя учителя являются локальной записью, а не защищённой подписью: авторизации нет, файлы редактируемы. Автоматические математические проверки не выдаются за учительское подтверждение.

Каждое полностью верное задание даёт 1 балл; частичных баллов нет. «5» — от 85%, «4» — от 65%, «3» — от 45%, иначе «2». Оценка считается до округления процента. Это шкала тренажёра, на скриншотах шкала отсутствует.

## Данные и ограничения

Данные находятся в localStorage этого браузера. Серверного кабинета, авторизации и автоматической доставки результатов нет. Очистка данных браузера удалит сохранённые попытки: перед этим следует скачать PDF/JSON. На общем компьютере результаты видны любому, кто откроет этот браузер.

Исходные ключи доступны в клиентском JavaScript, часы устройства и JSON редактируемы, журнал можно изменить. Это тренажёр для подготовки, а не защищённая система экзаменационного прокторинга. Системные окна могут вызывать потерю фокуса. При отказе Fullscreen API работа не начинается; режима обхода блокировки нет.

### Конструктор и уровни сложности

В разделе «Собери свою тренировку» есть вкладка **«ОГЭ · 9 класс»**; прямой адрес — `oge.html#builder`. В банке три учебных уровня: **«Разминка» — 64**, **«По демоверсии» — 272**, **«Усложнённый» — 64**. Для каждого №1–16 есть по четыре разминки и четыре усложнённых задачи. Меняются число шагов и структура решения: от прямого расчёта до нескольких изменений текста, отрицаний в логике, комбинированных запросов и путей с обязательными/запрещёнными вершинами. Это методическая классификация тренажёра, без официальной или статистической калибровки сложности.

Фильтры по сложности, номеру, теме, источнику и личному результату сочетаются с поиском. В карточке виден короткий фрагмент условия; полное условие можно раскрыть до выбора. Ключ и разбор появляются после завершения. После ввода имени и класса показан последний результат каждого условия: «Новое», «Решено», «Была ошибка» или «Ожидает проверки». №13.1 и №13.2 учитываются отдельно.

В подборке **1–100 разных условий**. Можно выбрать несколько версий одного номера, например десять задач №6 подряд. Одинаковый ID добавляется один раз, порядок меняется стрелками. Для каждой позиции отдельно сохраняются ответ, черновик, файл, автопроверка и учительский балл. Автоподбор распределяет выбор между доступными номерами и исключает уже пройденные ID по указанным имени и классу. Счётчик заранее показывает количество условий, разных номеров и доступный персональный остаток; невозможное количество не запускает подбор. Ручной выбор допускает намеренное повторение.

Время практики: **10, 20, 30, 45, 60, 90 или 150 минут**, либо **без таймера**. По умолчанию — 20 минут. Ограниченная практика автоматически завершается при истечении времени, в том числе после восстановления закрытой вкладки. Без таймера ученик завершает работу сам. Полный экран и автосохранение действуют в обоих режимах. Полный экзаменационный вариант сохраняет 150 минут и прежнюю шкалу, подборка получает баллы без отметки за весь экзамен.

Подборка сохраняется в браузере и переносится отдельным JSON-файлом `1430-oge-training`, schema 2: точные ID, порядок, формат №13 и длительность, без ответов и истории ученика. Файлы подборок schema 1 принимаются с длительностью 20 минут. Новый результат практики имеет schema 2 и массив `entries`; его `taskNumbers` — позиции, а `taskIds` связывает позиции с ID банка. Это позволяет повторять номера без перезаписи ответов и файлов. Старые результаты schema 1 сохраняют прежнюю структуру и полностью поддерживаются.

В отчёте кнопка «Повторить ошибки» предлагает **те же условия** или **новые аналоги той же сложности**. Во второй вариант попадают только ещё не пройденные ID тех же номеров и уровня. Если аналогов не хватает, показана причина; уровень автоматически не меняется. При отсутствии ошибок можно закрепить все задания. Формат №13 и выбранная длительность сохраняются; для прежней экзаменационной попытки предлагается короткая практика на 20 минут. Прежние 352 условия, ключи и ID сохранены.

### Случайные варианты и история ученика

Подбор учитывает завершённые попытки ученика по имени и классу. Регистр, лишние пробелы, ё/е и пробел в обозначении класса нормализуются. Пока доступные задания текущего круга не пройдены, использованные ID исключаются. Без предыдущей практики доступны 25 полных вариантов; новый круг начинается после исчерпания всех номеров. Для №13.1 и №13.2 история ведётся отдельно, остальные номера используют общую историю ученика. Фильтр сложности не создаёт отдельный круг: исчерпание выбранного уровня не разрешает повторять его при наличии других непройденных заданий. Практика schema 2 расходует те же ID общего банка, повторный импорт не дублирует прогресс.

Если отдельная практика раньше исчерпала один номер, он не повторяется автоматически: полный вариант временно недоступен, а сообщение и счётчики показывают номера для завершения круга. Новый общий круг начинается после исчерпания всех номеров для выбранного формата №13. Старые завершённые демоверсии учитывают исходные ID один раз. Повторный импорт той же работы не расходует дополнительные задания. История не синхронизируется между устройствами: её можно перенести импортом результатов.

Сначала собирается конкретный состав и открываются ссылки на его файлы. Подготовка и её отмена не расходуют задания; таймер начинается после явного запуска полного экрана. При запуске повторно проверяется актуальная история из localStorage: состав, устаревший после работы в другой вкладке, нужно собрать заново. Активная попытка сохраняет точные ID, порядок, ответы и вложения при перезагрузке; повторного подбора при восстановлении нет.

**После завершения ученик сразу получает автоматические учебные баллы, ошибки, тесты и разбор практики. Учителя ждать не требуется.** До завершения правильность и ключи не раскрываются. Можно повторно проверить вложения или создать новую практику по ошибочным номерам. Старые попытки с вложениями автоматически дополняются проверкой при открытии отчёта.

Параметры автопроверки берутся из известного ID задания в банке, а не из импортированного JSON. `autoChecks.taskId` должен совпадать с выбранным ID. При импорте файлы заново проверяются по текущей версии задания; сохранённым автоматическим баллам не доверяют. PDF содержит источник, ID, конкретное условие, критерии, баллы и разбор. Ручная корректировка учителя сохраняет прежний приоритет.

### Проверка исходной демоверсии

- №13.1, ODP: число и размер слайдов, заголовки, текстовые блоки, наличие реальных вложенных изображений, положение объектов, пропорции, стили/шрифты 40/24/20 пт и анимация. Наследуемые стили учитываются. Баллы 0–2 по проверяемым признакам критериев.
- №13.2, ODT: текст и допустимые ошибки, заголовок и два абзаца, таблица 9 × 2 с объединением строк 1 и 7, содержимое ячеек, 14 пт, отступы, интервалы, выравнивание, жирный/курсив/подчёркивание. Баллы 0–2, включая частичное выполнение.
- №14, ODS: сохранность исходных 1000 строк (сортировка допустима), ответы 107 и 230,63, настоящая круговая диаграмма с данными 219/198/210, легендой и числовыми подписями. Допустимы ответы в других ячейках вне исходных данных. Поддерживаемые формулы вычисляются безопасным парсером; устаревший кэш не принимается вместо результата формулы. По 1 баллу за каждый из трёх элементов.
- №15, Кумир / TXT: собственный интерпретатор команд Робота, 21 лестница с разными высотами подъёма/спуска, в том числе до 512 ступеней. Проверяются столкновения, завершение, пропуски и лишняя закраска. 2 балла за точное выполнение всех тестов; 1 — при завершении без аварии и не более 10 лишних / пропущенных клеток в каждом тесте; иначе 0.
- №16, Python / TXT: собственный ограниченный интерпретатор школьного Python. Три официальных теста ФИПИ дают 2/1/0 баллов по числу ошибок, ещё пять диагностических тестов выявляют границы диапазона, конец ввода и длинные последовательности. Дополнительные тесты показывают ошибки и пояснение, не меняя правило начисления баллов ФИПИ. Есть сравнение ожидаемого/полученного вывода. Поддерживаются присваивания, арифметика и остаток, сравнения, логика, `if/elif/else`, `while`, `for/range`, `break/continue`, списки, строки/индексы/срезы и школьные встроенные функции. `import`, `def`, произвольные атрибуты и внешние API не поддерживаются. Это не полный интерпретатор Python; неподдержанная конструкция обозначается как «не оценено», а не как неверная логика.

Презентация и документ включают смысловые и визуальные требования: автоматическая проверка доступных признаков не заменяет полноценную экспертную оценку. Для Робота конечный набор тестов не доказывает работу для бесконечного множества лестниц. Эти ограничения указаны рядом с результатом и в PDF; баллы обозначены как **учебная автоматическая оценка**. Учитель может при необходимости уточнить балл с комментарием; ручная оценка показывается отдельно и имеет приоритет. Кнопка «Вернуть автоматический балл» удаляет только ручную корректировку.

Неподдержанная формула ODS без числового кэша не объявляется ошибочным ответом: подтверждённые элементы сохраняют баллы, оставшийся элемент помечается «нужно пересчитать и сохранить файл». Итоговая отметка не ставится до проверки этого элемента; достаточно пересохранить ODS и повторить автопроверку. Повреждённый файл или отсутствие ответа дают явную диагностику. Техническая невозможность чтения и неподдержанная программа не превращаются в выдуманный нулевой балл.

### Файлы и выполнение

Форматы новых работ: 13.1 — `.odp`, 13.2 — `.odt`, 14 — `.ods`, 15 — `.kum` / `.txt`, 16 — `.py` / `.txt`. Старые результаты с другими языками продолжают импортироваться; автоматическая проверка для них явно не поддерживается, сохранённая учительская оценка сохраняется. Один файл до 5 МБ, все вложения попытки — до 32 МБ, переносимый JSON — до 64 МБ. При замене файла учитывается новый общий объём. Слишком объёмная сохранённая диагностика может быть опущена из пакета: импорт всё равно пересчитывает её из файлов. Код для фоновой проверки — до 200 КБ (интерпретатор ограничивает исходник 100000 символами). UTF-8 и Windows-1251 в коде поддерживаются.

Код ученика не передаётся в `eval`, `Function`, системные процессы или настоящий Python. Парсеры работают с ограниченным AST, у них есть пределы вложенности, шагов, размера данных и вывода; обработка программ вынесена в Worker с дополнительным тайм-аутом 10 секунд. ODF читается как ZIP + XML без выполнения макросов и внешних сущностей. ZIP-парсер проверяет заголовки/пути/CRC, ограничивает число записей (2000), отдельный распакованный файл (32 МБ) и общий объём (64 МБ). Зашифрованные и ZIP64-файлы явно не поддерживаются. Для Deflate нужен современный Edge/Chrome с `DecompressionStream('deflate-raw')`. Никаких сетевых сервисов проверки нет: проверка выполняется в браузере на устройстве ученика.

Для XML установлены ограничения 8 МБ, 100000 элементов и глубина 128. Повторяемые строки и столбцы проверяются до разворачивания: максимум 100000 заполненных ячеек. Пересчёт формул использует общий бюджет на всю таблицу, запоминает вычисленные зависимости, выявляет циклы и устаревший кэш. Превышение бюджета оставляет неподтверждённый критерий без выдуманного балла.

Данные ОГЭ: localStorage `1430.oge.v1.active` / `.results` (ответы, оценки, диагностика), `.builder` (выбранные ID, порядок и формат №13), IndexedDB `1430-oge-files` (бинарные вложения). `autoChecks` сохраняет критерии, статус, баллы, версию проверяющего, дату и SHA-256 файла. Смена/удаление вложения отменяет его предыдущую проверку. Во время прохождения автопроверка не показывается; после завершения файлы проверяются и только затем появляется отчёт. При перезагрузке ответы и вложения сохраняются.

«Результат ОГЭ с файлами» создаёт JSON-пакет с base64-вложениями. Импорт не доверяет переданным автоматическим баллам: они заново вычисляются из байтов файлов. Создаётся новый локальный ID. Учительские корректировки остаются отдельными метаданными, это не защищённая подпись. PDF содержит баллы, критерии, ошибки, ожидаемый и полученный вывод, разборы, имена вложений, черновики и журнал; сами файлы передаются JSON-пакетом. Серверной аттестации и авторизации нет.

Перед стартом скачайте и распакуйте материалы. При переходе во внешний редактор ввод в браузере блокируется, таймер идёт. После возвращения требуется явный возврат в полный экран. Калькулятор остаётся учебной помощью. Закрытие вкладки можно предупредить, но сайт не может запретить его.

Полный вариант получает учебную отметку по рекомендованной шкале 2026: 0–4 → 2, 5–10 → 3, 11–16 → 4, 17–21 → 5. Источник: https://doc.fipi.ru/oge/normativno-pravovye-dokumenty/04-44_18.02.2026.pdf . Для проекта 2027 шкала явно обозначена как ориентир; практика по номерам отметку за полный ОГЭ не получает.
