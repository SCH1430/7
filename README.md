# Седьмое — тренажёр задания №7 ЕГЭ по информатике

Готовый статический сайт на русском языке. Работает на **GitHub Pages без сервера, сборки, внешних библиотек, шрифтов и API**. Интерфейс адаптирован к компьютерам, планшетам и телефонам.

## Возможности

- Перед началом: имя, фамилия и класс.
- 8, 12, 16 или 24 задания; 15, 30, 45 или 60 минут. По умолчанию — 12 заданий на 30 минут.
- 12 генераторов с изменяющимися числами. Случайный порядок; точные повторы в одной работе исключены. В каждой работе представлены все три темы. При 12 заданиях встречается каждый тип.
- Навигация по номерам, отметки «на потом», сохранение ответов при вводе.
- Абсолютный срок окончания: фоновые вкладки, перезагрузка и закрытие страницы не ставят таймер на паузу. При возвращении после срока работа завершается автоматически.
- Полный экран по выбору; корректная работа при отказе или отсутствии поддержки браузером.
- Журнал потери фокуса, скрытия страницы, выходов из полного экрана и восстановлений после загрузки. Одновременные `blur` и `visibilitychange` объединяются в одно событие.
- Итоговая оценка, результаты по темам, фильтр ошибок и пошаговые решения.
- Отчёт `.txt` для передачи учителю; печать или сохранение в PDF средствами браузера.
- Результат последней работы сохраняется локально. Новая работа заменяет предыдущую; отчёт стоит скачать заранее. Кнопка удаления стирает сохранённые данные.
- На HTTPS / localhost браузеры с Web Locks не позволяют двум вкладкам одновременно менять сохранённую работу.

## Размещение на GitHub Pages

### Вариант 1 — с автоматической проверкой (рекомендуется)

1. Создайте репозиторий GitHub, например `ege7-trainer`, с основной веткой `main`.
2. Загрузите **содержимое этой папки в корень репозитория**, включая скрытую папку `.github` и файл `.nojekyll`. `index.html` должен лежать в корне, а не в дополнительной вложенной папке. Для загрузки скрытых файлов удобнее Git / GitHub Desktop.
3. Откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
4. В разделе **Actions** откройте **Check and deploy GitHub Pages** и запустите **Run workflow**, если последний запуск был до включения Pages. Последующие изменения ветки `main` публикуются автоматически.
5. После успешного завершения адрес сайта появится в **Settings → Pages** и в окружении `github-pages`. Для такого имени репозитория адрес обычно имеет вид `https://ВАШ-ЛОГИН.github.io/ege7-trainer/`.

Workflow проверяет синтаксис и расчёты задач, затем публикует только файлы сайта. На pull request запускаются проверки без публикации. Если основная ветка называется иначе, замените `main` в `.github/workflows/pages.yml`.

### Вариант 2 — загрузка файлов через браузер

1. Загрузите `index.html`, `styles.css`, `favicon.svg`, папку `js` и пустой файл `.nojekyll` в корень репозитория.
2. Выберите **Settings → Pages → Source → Deploy from a branch → main → / (root) → Save**.
3. Дождитесь публикации. Папка `.github` для этого способа не нужна; если используете только этот способ, не загружайте её.

Относительные пути работают как на `username.github.io`, так и в подпапке репозитория. Настройки `base`, маршрутизатор и перенаправление 404 не требуются.

Документация GitHub: [источник публикации GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

## Локальный запуск

В папке проекта выполните:

```sh
python3 -m http.server 8000
```

Откройте `http://localhost:8000`. Можно также открыть `index.html` напрямую, но автосохранение и Web Locks зависят от ограничений браузера для `file://`. Для проверки полного экрана и сохранения используйте localhost или HTTPS.

## Типы задач

| Изображения | Звук | Передача данных |
| --- | --- | --- |
| Объём растрового изображения | Объём аудиозаписи | Время передачи изображения |
| Максимальная палитра по памяти | Максимальная длительность | Передача сжатого звука |
| Изменение разрешения сканирования | Глубина кодирования | Пакет фотографий с заголовками |
| Палитра со сжатием и заголовком | Изменение частоты, глубины и каналов | Минимальная скорость канала |

Задания авторские, генерируемые; не являются дословной копией банка ФИПИ. Тематическая основа: определение памяти для хранения графической и звуковой информации — [навигатор ФИПИ по информатике, 2026, задание №7](https://doc.fipi.ru/navigator-podgotovki/navigator-ege/2026/Inf_2_teoriya.pdf). Сервис не связан с ФИПИ.

Во всех задачах явно приняты единицы: 1 Кбайт = 1024 байта, 1 Мбайт = 1024 Кбайт, 1 байт = 8 бит. В задачах на максимум целого количества применяется округление вниз, на минимум достаточной скорости — вверх. Допустимы дробные ответы с точкой или запятой. В задачах на палитру число бит на пиксель целое.

## Учебная пятибалльная шкала

| Оценка | Доля верных ответов |
| --- | --- |
| 5 | от 85% до 100% |
| 4 | от 70% до менее 85% |
| 3 | от 50% до менее 70% |
| 2 | от 20% до менее 50% |
| 1 | менее 20% |

Каждое задание имеет одинаковый вес. Пустые и неверные ответы дают 0, верный — 1. Оценка вычисляется по точной доле **до округления** отображаемого процента. Шкала учебная и не соответствует первичным или тестовым баллам ЕГЭ. События активности не уменьшают оценку.

## Что означает мониторинг

Обычная веб-страница может наблюдать только собственную видимость, фокус и состояние полноэкранного режима. Она **не умеет перечислять вкладки, читать другие сайты или гарантировать отсутствие списывания**. Открытая в фоне вкладка без ухода с тренажёра может не вызвать события. Переход в другую программу, адресную строку или системный диалог может вызвать потерю фокуса.

Полный экран включается с разрешения браузера, пользователь может выйти из него. На части мобильных браузеров Fullscreen API недоступен; работа в таком случае продолжается, в отчёте это указано. При закрытии браузера точная длительность отсутствия неизвестна: восстановление оценивает её по последней сохранённой отметке, не выходя за срок работы.

GitHub Pages — статический хостинг. **Он не отправляет результаты учителю и не предоставляет учительскую панель в реальном времени.** Имя, класс, ответы и журнал сохраняются только в `localStorage` текущего браузера. Для передачи результата ученик скачивает отчёт. На общем компьютере удаляйте работу после экспорта.

Это учебный контроль активности, а не защищённый прокторинг. Код, ответы, часы и локальные данные доступны пользователю; отчёт не подписан сервером. Для защищённых экзаменов, централизованного журнала и независимого времени понадобится отдельный сервер и аутентификация.

## Структура

```text
index.html                   Стартовый экран и каркас приложения
styles.css                   Адаптивное оформление и печать
favicon.svg                  Значок сайта
js/tasks.js                  Генераторы, условия, ответы и решения
js/core.js                   Проверка ответов, шкала, таймер и модель работы
js/app.js                    Интерфейс, события браузера и сохранение
tests/core.test.cjs           Проверки расчётов и модели
tests/browser.html            Изолированные проверки интерфейса в браузере
.github/workflows/pages.yml  Проверки и публикация
.nojekyll                    Отключение обработки Jekyll
```

## Проверки

Нужен Node.js 20 или новее; устанавливать пакеты не требуется.

```sh
npm run check
npm test
```

Тесты проверяют 6000 сгенерированных задач независимыми формулами/неравенствами, разнообразие и воспроизводимость вариантов, границы оценок, ввод дробей, восстановление срока, завершение и объединение событий активности.

После запуска локального сервера откройте `http://localhost:8000/tests/browser.html` и нажмите «Запустить проверки». Три дополнительных сценария проверяют автоматическое завершение по времени, восстановление и навигацию, объединение событий, выход из полного экрана, ручное завершение, фильтры, подготовку печати и работу при запрещённом хранилище. Используется изолированное хранилище в iframe; данные основной страницы не меняются. Этот файл не включается в публикацию через готовый GitHub Actions workflow.

Для ручной проверки откройте сайт, начните работу, введите несколько ответов, поставьте флажок, переключите вкладку и вернитесь, выйдите из полного экрана, обновите страницу и завершите работу. Проверьте сохранность ответов, итоговый журнал, разбор и скачивание отчёта. Отдельно проверьте узкое окно и истечение таймера.
